# Test Script: Rationale Prototype (Cold Read)

Task B4. Use with `.meta/prototypes/rationale-item-01.md`.

## Setup (read this to the colleague, nothing more)

You are a TARA analyst. A tool has read a client's documents for a certificate management portal, and it has built an Item Definition without stopping to ask anyone. You are now checking how it did that. The two pages show what it produced and, under "Rationale", every point where it had to judge. You have not been briefed on the tool. Think aloud while you read.

## Tasks

1. Find what the tool assumed about the internet-facing load balancer. Say whether you agree.
2. Go through the "Needs your attention" items on both pages. Mark each one you would confirm, and each one you would dispute, with a one-line reason.
3. Point out anything unclear: a word, an item you could not place, a question you would not send to a client as written.
4. Say whether anything important is missing from the Rationale.

## Observer notes

- Note every time the colleague asks "why?" or "where does this come from?".
- Note how long each page takes.
- Do not explain anything unless the colleague is completely stuck; if you do, note it.

## Overall questions (after the tasks)

1. Could you tell, from the Rationale alone, on what basis the Item Definition was made?
2. Were there too many items, too few, or about right?
3. Was "Needs your attention" versus "For information" the right split?
4. Would you trust this enough to review only the Rationale, instead of redoing the Item Definition?
